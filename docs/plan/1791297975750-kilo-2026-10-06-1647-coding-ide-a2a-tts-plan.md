# Coding IDE mit A2A-Agenten & Spokenword-TTS

**Model:** Kilo
**Datum/Zeit:** 2026-10-06 16:47 UTC
**Plan-ID:** 1791297975750

## Ziel

Web-basierte Coding-IDE in der mehrere KI-Agenten (A2A) gemeinsam Software entwickeln, debattieren und per Spokenword (TTS) ihre Argumente hörbar machen. Die UI passt sich live an den aktuellen Codierungs- und Debattenzustand an (GenUI-Renderer + Live-Preview). Agenten laden ihre Fähigkeiten dynamisch aus dem vorhandenen Skill-Generator.

## Datenflüsse

1. **User-Intent** → IDE-Frontend → Gateway POST `/ide/request`
2. **Planungs-Debatte**:
   - Gateway startet dynamisch N Agenten (Planner, Coder, Reviewer, ggf. mehr), jeder lädt seine `SKILL.md` über `skill-generator`
   - Agenten posten Argumente auf A2A-Bus (Server-Sent Events)
   - Jedes Argument wird parallel an `/tts` (Spokenword) geschickt → Audio-Stream zurück ans Frontend
   - Debate-Stream rendert Genui-Card (Sprecher-Name, Text, Audio-Player, Vote-Button)
3. **Code-Phase**:
   - "Coder"-Agent erzeugt JSON-Schema (Komponentenbaum der UI), streamt via `chat-completions`
   - Frontend füttert `GenuiRenderer` mit `isJsonComplete=false` → live UI-Anpassung
   - Parallel: `generateCode` erzeugt Vue-SFC → Monaco zeigt Source
4. **Validation**: Tester-Agent läuft Sandbox-Code, meldet Diff → Renderer hebt Fehler hervor

## Kernkomponenten (Implementations-Reihenfolge)

### 1. Skill-Loader Service
- Liest `skills/*/SKILL.md` + `reference/` (Output von `skill-generator`)
- Stellt Agenten via `/skills` Endpoint bereit
- Wird in jedem Agent beim Start aufgerufen
- Datei: `ide-gateway/src/skills/loader.ts` (neu)

### 2. A2A-Gateway
- Erweitert `webui-sdk/sites/playground/server/src/a2a-tools/` um:
  - **Debate-Orchestrator**: Round-basierte Moderation, Konsens-Erkennung
  - **Skill-Mount**: injiziert SKILL.md in System-Prompt jedes Agenten
  - **TTS-Bridge**: bei jedem `text`-Event POST `/tts` mit Sprecher-Voice, gibt `audio_url` zurück
- Datei: `ide-gateway/src/orchestrator/debate.ts` (neu)

### 3. Frontend IDE-Shell
- Vue 3 App, Routing: `/editor`, `/debate`, `/agents`, `/preview`
- Komponenten:
  - `MonacoEditor.vue` (Code-Ansicht, Read/Write-Diff)
  - `DebateStream.vue` (GenuiChat-Instanz + Audio-Player je Message)
  - `AgentBoard.vue` (Live-Status jedes Agenten, A2A-Card-Ansicht)
  - `LivePreview.vue` (GenuiRenderer-Instanz mit Streaming-Schema)
  - `Toolbar.vue` (Start Debate, Spawn Agent, Export SFC)
- Verwendet `@opentiny/genui-sdk-vue` als npm-Dependency
- Pfad: `ide-frontend/src/` (neu)

### 4. TTS-Integration
- Spokenword-Server läuft als Sidecar (Port 8000)
- Frontend ruft pro Agent-Message `POST /tts` mit Voice pro Agentenrolle
- Audio wird über `<audio>` mit `data-audio="stream"` live abgespielt
- Konfig: `ide-gateway/config/voices.json` (Map agent-role → wav-Datei)

### 5. Dynamic Agent Spawning
- `POST /agents/spawn` mit `{role, skills[], model}` → startet Sub-Prozess
- Jeder Agent implementiert A2A-Server (`@a2a-js/sdk`) auf eigenem Port
- Gateway registriert AgentCard automatisch im A2A-Bus

## UI-Anpassung (Schema-Driven)

Der GenuiRenderer rendert das, was Agenten gerade generieren:

| Agent-Phase | Schema-Output | UI-Effekt |
|---|---|---|
| Plan-Debatte | `{componentName:'DebateBubble', props:{speaker,text,audioUrl,votes}}` | Karten-Stream mit Play-Buttons |
| Code-Generierung | `{componentName:'Page', children:[...]}` | Live-Preview-Panel rendert Komponente |
| Test-Result | `{componentName:'TestReport', props:{passed,failed,logs}}` | Test-Tab aktualisiert sich |
| Export | (kein Schema, SFC-Download) | Monaco zeigt `panelValue` |

## Validierung

1. **Build**: `pnpm -C ide-gateway build` und `pnpm -C ide-frontend build` ohne Fehler
2. **Smoke-Test**: `node ide-gateway/scripts/smoke.mjs`

## Out of Scope (später)

- Multi-Tenant / User-Accounts
- Persistenz der Debatten (nur In-Memory)
- Voice-Cloning pro User (nur vordefinierte Voices)
- Mobile-Layout (Desktop-First)
- GPU-Inferenz (CPU-only via pocket-tts)

## Offene Risiken

1. **TTS-Latenz**: Pocket-TTS streamt pro Chunk — langer Text → wahrnehmbare Verzögerung. Mitigation: Sentence-Splitting vor `/tts`-Call.
2. **Schema-Stream-Race**: Wenn mehrere Agenten parallel streamen, überschreiben sich Renderer. Mitigation: Pro Agent eigene `GenuiRenderer`-Instanz mit `id`.
3. **AgentCard-Discovery**: Lokale Agenten müssen ihre Card vor erstem Aufruf veröffentlichen. Mitigation: `/agents/well-known/agent.json` Polling beim Gateway-Boot.
